# Succinct Civilization Ledger

Succinct Civilization Ledger is a research-style Flask system for storing thousands of years of civilization history as a financial ledger, compressing the historical text and numeric scores, and searching it with both exact compressed indexes and AI semantic embeddings.

## What It Does

Each event becomes a ledger entry:

| Field | Meaning |
| --- | --- |
| Civilization Name | Roman Empire, Maurya Empire, Abbasid Caliphate |
| Year / Era | Numeric year, BCE as negative |
| Type | `Asset` or `Liability` |
| Domain | `Economic`, `Military`, `Governance`, `Scientific`, `Social` |
| Value | Numeric strength or risk score |
| Description | Historical evidence text |

Core stability formula:

```text
Civilization Stability = Total Assets - Total Liabilities
```

AI-weighted scoring:

```text
Score = Weighted Assets - Weighted Liabilities

Economic   = 0.30
Military   = 0.25
Governance = 0.20
Scientific = 0.15
Social     = 0.10
```

Example:

```text
Assets: Military 88, Social 55
Liability: Governance 62
Weighted score = 88*0.25 + 55*0.10 - 62*0.20 = 15.10
Raw stability = 143 - 62 = 81
```

## Architecture

Flowchart:

```text
Wikipedia / DBpedia / Seshat / CSV / JSON
        ↓
Raw historical text and records
        ↓
Ledger conversion: Asset or Liability + domain + value
        ↓
PostgreSQL or SQLite tables
        ↓
Compression layer: FM Index for descriptions, Wavelet Tree for scores
        ↓
AI layer: sentence-transformers embeddings + FAISS vector search
        ↓
APIs and UI: search, scoring, import, analytics
```

Block diagram:

```text
Frontend
   ↓
Flask Backend APIs
   ↓
Database
   ↓
Compression Engine ── FM Index, Suffix Array, BWT, Wavelet Tree
   ↓
AI Engine ── Sentence Transformers, FAISS, optional regression scoring
```

## Database Design

Tables:

```sql
CREATE TABLE civilizations (
    id INTEGER PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    name TEXT NOT NULL UNIQUE,
    region TEXT,
    start_year INTEGER,
    end_year INTEGER,
    notes TEXT
);

CREATE TABLE ledger_entries (
    id INTEGER PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    civilization_id INTEGER NOT NULL REFERENCES civilizations(id) ON DELETE CASCADE,
    year INTEGER NOT NULL,
    entry_type TEXT NOT NULL CHECK (entry_type IN ('Asset', 'Liability')),
    domain TEXT NOT NULL CHECK (domain IN ('Economic', 'Military', 'Governance', 'Scientific', 'Social')),
    value REAL NOT NULL,
    description TEXT NOT NULL,
    source TEXT DEFAULT 'manual',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

Insertion code is in `backend/database.py`:

```python
db.register_civilization("Roman Empire", "Mediterranean", -27, 476)
db.add_ledger_entry(
    civilization_id=1,
    year=117,
    entry_type="Asset",
    domain="Military",
    value=88,
    description="The army secured frontier defenses and expanded imperial roads.",
    source="manual",
)
```

## Required Data Structures

### A. Suffix Array

A suffix array stores all starting positions of suffixes of a text in sorted order.

For text:

```text
banana$
```

Suffixes:

```text
0 banana$
1 anana$
2 nana$
3 ana$
4 na$
5 a$
6 $
```

Sorted suffix array:

```text
[6, 5, 3, 1, 0, 4, 2]
```

Pattern search uses binary search over suffixes. In this project, `SuffixArray.search("army")` returns positions where `"army"` occurs in ledger descriptions.

Complexity:

```text
Build: O(n log n) in this educational implementation
Search: O(m log n), where m is pattern length
```

### B. Burrows-Wheeler Transform

BWT rearranges text by sorting rotations or, equivalently, using suffix-array order and taking the character before each suffix.

For:

```text
banana$
```

Suffix array:

```text
[6, 5, 3, 1, 0, 4, 2]
```

BWT characters:

```text
suffix at 6 -> previous char a
suffix at 5 -> previous char n
suffix at 3 -> previous char n
suffix at 1 -> previous char b
suffix at 0 -> previous char $
suffix at 4 -> previous char a
suffix at 2 -> previous char a
```

BWT:

```text
annb$aa
```

Why it helps compression: repeated contexts are grouped together. Text with many repeated words like “army”, “governance”, “trade”, and “taxation” forms local clusters that run-length or entropy coders can compress well.

### C. FM Index

The FM index combines:

- BWT
- suffix array samples or positions
- `C[ch]`: first position of each character in sorted BWT
- `Occ(ch, i)`: number of occurrences of `ch` in BWT before position `i`

Backward search pseudo-code:

```text
top = 0
bottom = len(BWT)
for char in reversed(pattern):
    top = C[char] + Occ(char, top)
    bottom = C[char] + Occ(char, bottom)
    if top >= bottom:
        return no match
return suffix_array[top:bottom]
```

The important idea: the query runs on the compressed BWT representation. It does not need to reconstruct the full text to find matching rows.

Implementation: `backend/compression.py`, class `FMIndex`.

### D. Wavelet Tree

A wavelet tree stores a numeric sequence by recursively splitting values into lower and upper halves.

Example scores:

```text
[88, 62, 55, 82, 48, 75]
```

At each node:

- compute midpoint of value range
- write `0` for values in the lower half
- write `1` for values in the upper half
- recurse on both halves

Supported queries:

```python
tree.rank(82, index=6)       # occurrences of 82 in first 6 values
tree.range_count(50, 90)     # number of scores from 50 to 90
```

Complexity:

```text
Construction: O(n log σ), σ = numeric value range
Rank: O(log σ)
Range count: O(log σ) for aligned ranges, often O(log σ + output partitions)
```

## Compression Layer

Text descriptions:

```text
description strings → suffix array → BWT → FM index
```

Numeric values:

```text
ledger values → integer score sequence → wavelet tree
```

Memory reduction:

- BWT clusters repeated historical language for later compression.
- FM index avoids scanning every description for exact pattern queries.
- Wavelet tree avoids storing many separate numeric indexes for range/rank analytics.

Search examples:

```text
Exact query: army
Result: every ledger event whose compressed indexed description contains army.

Semantic query: ethical governance
Result: entries about Ashoka, welfare officers, legitimacy, law, reform, etc.,
even if the exact words differ.
```

## Implementation Notes

- `sentence-transformers` and `faiss` are used when installed and available.
- If model loading fails, the app falls back to TF-IDF search so the UI still works.
- PostgreSQL is supported through `DATABASE_URL`.
- SQLite fallback lets you start coding before your PostgreSQL database is ready.
- The compression code is educational and readable. For production-scale FM indexes, use sampled suffix arrays, compressed bitvectors, and disk-backed vector stores.
